# Artwork-first saved-material intake

The daily product starts with one strong unused saved artwork. The plate is an original landscape transformation and remains the interface. Six distinct source windows is desirable only when supported; one compelling source is valid and zero is invalid. Do not manufacture independence by binding several objects to duplicate copies of one source.

## Why the previous intake failed

The previous reader enumerated authorized files, reverse-sorted full paths, and refreshed at most48 changed notes from a persistent lexical scan cursor. Nomination then operated only on that partially populated cache. A bounded metadata prefix could spend the entire paid-work opportunity on an unsuitable thematic folder, despite saved media elsewhere. The October22 retained run acquired six Crypto & Network Economies posts, inspected zero pixels and admitted zero sources; those exclusions were appropriate. Its cache contained48 entries, including33 from that folder, with scan/selection cursors still in the folder. This is not evidence of external artwork shortage. A deterministic fixture with60 commentary notes ahead of one media-bearing artwork reproduces the lost coverage.

## Replacement

1. Build/update a **local** metadata index across the explicitly authorized saved lanes: `Inbox/tweets`, `00 - Capture/tweets`, `01 - Active/themes`, `Themes`. Re-stat entries and reread changed notes only. Bound traversal to1000 directories/10000 files, each note to128KiB, changed bytes to32MiB and the isolated worker to20seconds. Incomplete access fails explicitly, never silently nominates a partial index.
2. Nominate a small deterministic batch, at most24 owners. Four simple lanes use owning prose and attached-media identities: media plus described creative work; described creative work needing media resolution; other attached media; sparse owning bookmarks awaiting acquisition. Folder names and tags confer no eligibility. Stable owning-identity ordering and a cursor across the entire priority queue prevent both thematic path concentration and repeated strong-label negatives starving sparse artwork; no all-vault LLM ranking occurs.
3. Apply complete archive dedupe to the anchor lane's canonical parent and attached-media identities, then ordinary fetch/text/actual-pixel admission. Saved status and metadata are nominations, not stamps. Existing high-confidence pixel, provenance and editorial-exclusion gates remain mandatory.
4. Select the first usable strong work and deepen its research. Then continue toward six windows through the supporting lane described below. Optional prepared reserves can retain useful acquisitions but are not a readiness prerequisite. Report metadata reads separately from bounded paid acquisitions and pixel inspections.
5. Generate only supported real windows. Preserve original landscape, source fidelity without overcopy, exact media, readable desktop/mobile open states, full applicable QA and independent review. Register accepted proof through the existing sole-sender watchdog; keep07:00 fallback/repair ownership unchanged.

## Supporting-window repeats

Nick, 2026-11-13: “the main artwork should stay new while the supporting windows repeat.” Before this change the last 22 editions each had exactly one X window: intake read only X bookmarks, acquisition stopped at the first admitted work, and the full one-use ledger had exhausted the music/video pools.

**Anchor / main artwork — unchanged strictness.** The anchor source, the dominant plate source (`selected_image_material[0]`) and the visual reference are blocked if any `url`, `source_url`, `final_url`, `resolved_url`, `page_url`, `image_url`, `source_image_url`, `source_media_url`, inspected `media_url`, image alias or X/Twitter status family (same status ID under any username, `i/web` or twitter.com spelling) appears anywhere in the published archive, any age, same date included. `source-research.json.anchor_archive_repeats` must be empty or research throws before image generation.

**Supporting windows — 30-day cooldown.** A previously published source may return as a supporting window when it was not used (as anchor or supporting) in any edition dated within `SUPPORTING_REPEAT_COOLDOWN_DAYS` (30, `scripts/lib/source-ledger.mjs`) of the run date — the run date itself and later included — and not in the immediately previous published edition, however old. A former anchor may return only as a supporting window after the cooldown, never as an anchor. One source family per edition. Fresh material outranks a cooldown repeat of equal merit. A plain `Set` ledger, or one built without a run date, stays fully strict (reserve preparation is unchanged).

**Multi-channel supporting intake.** Ordinary `obsidian-allowlist` bookmark-first intake keeps the fresh-only X anchor queue (`intake_lane: 'anchor'`) and adds a bounded supporting lane (`intake_lane: 'supporting'`, at most 18 nominations) read in the same killable vault worker: `00 - Capture/youtube` and `Inbox/youtube` likes, the eight NTS liked-track source maps (existing high/medium confidence, direct-stream row filter) and `00 - Capture/frontpage-intake` manual curation. Candidates blocked by the cooldown are dropped; fresh rows sort before cooldown-eligible repeats, with a per-day deterministic rotation, and channels are round-robined. `signal-harvest.json.selection_policy.supporting_intake` reports per-channel counts. Nominations confer no eligibility.

**Acquisition.** Phase 1: single anchor-lane works until one *anchor-eligible* work admits — the same `hasCreativeArtifactEvidence` + `decideAnchorEligibility` test against the FULL archive ledger that later picks the anchor. A work admitted only as a supporting window (for example a fresh X status whose fetched media was published long ago) neither ends Phase 1 nor opens the supporting lane, so the X lane keeps pulling within the 24 budget and no supporting fetch is spent when no fresh anchor exists. Phase 2 interleaves remaining anchor-lane works and supporting candidates by channel in small batches (at most the remaining shortfall to six) under the same shared 24-acquisition / 24-inspection budget, and also continues while no anchor-eligible work remains selected. `bookmark-acquisition.json` reports `anchor_lane_acquired`, `supporting_lane_acquired`, `admitted`, `anchor_eligible_admitted`, `target` and the ledger policy. Fewer than six real windows remains valid; never pad, split or add summary cards. Editorial exclusions, high-confidence actual-pixel admission, exact-tuple/digest-verified inspection reuse, real-mark mapping, landscape and fidelity gates are unchanged.

**Legacy / broad-field selection.** Outside bookmark-first intake, the inspection candidate field (`selectSourceCandidatesForInspection`) still uses the full ledger, so repeats are not fetched as candidates. But final window selection (`selectContentSources`), autoresearch selection normalization, research evidence scoring and creative-inspection eligibility all apply the cooldown subset to supporting windows; so already-fetched material such as anchor-derived pages or image-material sources may appear as supporting windows after the cooldown. The anchor, dominant plate source and visual reference stay checked against the full archive in every mode.

**Material keys.** X media spellings `pbs.twimg.com/media/<id>.jpg`, `<id>.jpg:large`, `<id>?format=jpg&name=…` canonicalize to one key (`pbs.twimg.com/media/<id>`), and `mobile.twitter.com` normalizes to `x.com`, in `canonicalizeSourceUrl`, the main-process ledger and the intake worker's `materialKey`.

**Archive validation.** Packages mark each binding `archive_role: 'anchor' | 'supporting'` (anchor = researched anchor source, else dominant plate source page, else the hero binding). `validate:editions` applies `archiveSourceRepeatViolations` to editions dated from 2026-10-22: an edition carrying role tags must mark exactly one `anchor` (an all-`supporting` package fails); anchor/unmarked bindings may not repeat any prior edition; supporting bindings may not repeat a prior edition inside the cooldown or the previous edition; no duplicate family within an edition. Earlier published editions are not rewritten. Tests: `tests/node/supporting-window-*.test.mjs`, `tests/node/archive-source-policy.test.mjs`, `tests/node/material-key-canonicalization.test.mjs`.
